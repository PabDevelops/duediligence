# Contención del gasto de traducciones

Las consultas anónimas, los buscadores y la hidratación automática no pueden iniciar traducciones de pago. Se requiere una sesión registrada y confirmada, validada mediante Supabase `auth.getUser()` en el servidor. Una cookie de visitante, un identificador enviado por el cliente o una sesión anónima no autorizan gasto.

Límites fijos: 5 intentos por usuario y día, 50 entre todos los usuarios y servidores, con reinicio a las 00:00 UTC. El servidor reserva antes de llamar al proveedor mediante una transacción con bloqueo compartido de Postgres. Un hash del texto impide dos intentos para la misma entrada en un día. Los errores y tiempos agotados consumen su reserva porque pueden haber sido facturados; no hay reintentos automáticos. Entrada máxima: 4.000 caracteres; salida máxima: 256 tokens. Son límites de llamadas y tamaño, no un importe monetario exacto.

La tabla dedicada `ai_translation_usage` guarda estado e información de tokens devuelta por el proveedor, sin el texto fuente, correos ni claves. Está cerrada a `anon` y `authenticated`, con RLS habilitado sin políticas de acceso de navegador. El aviso informativo del asesor sobre ausencia de políticas es deliberado: solo `service_role` tiene permisos. El RPC usa `security invoker`; no se conceden permisos nuevos sobre `auth.users`. La sesión se comprueba en el servidor y la relación con el usuario se mantiene mediante clave foránea.

Si falla la autenticación, la reserva o la base de datos, no se llama a Claude. La ficha conserva los datos financieros y muestra la descripción original cuando no hay traducción. Las traducciones existentes se mantienen compartidas y no se reemplazan por el inglés del proveedor para volver a cobrarlas. Las descripciones nuevas se traducen durante una actualización financiera solicitada por un usuario registrado; no se añade una cola ni un proceso en segundo plano.

Validación: 854 pruebas automatizadas, incluidos visitantes, cookies falsas, sesiones anónimas/no confirmadas, agotamiento/error de presupuesto, errores de autenticación, clave ausente, límites de tamaño, tiempos agotados y traducciones truncadas. La prueba de API verifica conservación de una traducción española ante un refresco que devuelve inglés. Comprobación transaccional real de permisos, reservas, duplicados y ambos topes, con rollback: cero reservas de prueba persistentes y cero llamadas pagadas. Build completo, ESLint y controles de GitHub antes de integrar.

Alcance: no cambia fórmulas, fuentes financieras, puntuaciones, cuentas, carteras ni correcciones manuales. El generador del blog sigue siendo una función administrativa separada; este límite protege las traducciones de fichas y no sustituye los controles de gasto del proveedor sobre otros usos de la misma clave.
