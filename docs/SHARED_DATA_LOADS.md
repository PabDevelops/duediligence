# Carga de datos y retirada del screener

El screener se retira por petición del usuario. La ruta antigua redirige a `/search`; su API devuelve 410 sin importar autenticación, base de datos ni cargadores financieros. No puede iniciar ni renovar el escaneo del universo. Se eliminan sus accesos de navegación y las tarjetas/promesas de la función en las áreas comerciales principales. Las preferencias de navegación guardadas omiten el elemento retirado sin modificar los registros de usuarios. El código anterior permanece en Git; los módulos auxiliares conservados no tienen un endpoint público que los ejecute.

La optimización experimental de cursor del PR83 se excluye del resultado final. Se conserva del PR82 la coalescencia de cargas y sus pruebas, pero el endpoint del screener queda completamente desactivado. No se prolonga el trabajo para recuperar una función que ya no se quiere ofrecer.

El calendario mantiene grupos de 50 y dos consultas de enriquecimiento simultáneas por instancia, compartidas entre rangos. Agrupa peticiones equivalentes y reutiliza ventanas públicas en la caché existente de Next con revalidación de 90 segundos, separadas por commit y día. No persiste un fallo como calendario vacío; cada cliente recibe su propia respuesta legible. Se conservan los eventos, cálculos, deduplicación y orden. La primera carga de una ventana nueva todavía depende de la latencia de Finnhub/Nasdaq y Supabase; los resultados posteriores pueden reutilizarse entre instancias.

Medición previa: portada 0,33 s; ficha AAPL 10,21 s; API AAPL y screener >45 s. Antes de desplegar, otra medición ya devolvió AAPL en 0,64 s y screener en 34,65 s sin registros: parte de la incidencia es intermitente. Después del PR82, AAPL fue 0,44 s, su ficha 0,8 s y el calendario devolvió 1.992 eventos; el screener seguía sufriendo timeout SQL 57014. Esa función se retira y no se presenta como reparada.

Validación final: 864 pruebas, incluidas llamadas antiguas de API con parámetros y sesión sin acceso a autenticación o datos. Build completo y regresiones de concurrencia del calendario. Los resultados conectados de la retirada se entregan al cerrar el trabajo. No cambian fórmulas, fuentes, notas, cuentas, carteras, correcciones manuales, esquema, planes contratados ni staging.
